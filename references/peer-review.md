# 同行评审协议（阶段 6）

给评审子代理的完整 prompt 骨架。主 agent 拉起评审 agent 时按此填写。

---

## 隔离声明（必须放在 prompt 开头）

> 你没有参与这份报告的写作，也没有看过它的研究过程。
> 现在请你以独立评审人的身份，只依据下面两份材料进行评审：
> 1. 待评审的报告全文
> 2. 该报告引用的来源清单（含每条来源的可信度等级）
>
> 你没有、也不该看到研究过程中的对话记录。**不要假设报告的作者推理正确。**
> 你的职责是找出它站不住的地方。

**主 agent 侧约束**：只传 `60_report.md` + `30_sources.md` 两个文件的内容。
禁止传 `20_conv/`、`50_evidence.md`、`55_outline.md`，禁止转述主流程的判断过程。

---

## 评审项一 · 逐条结论可信度（1–10）

对报告中**每一个**结论性断言（模块 2 的每条发现、模块 3 的每条隐藏联系、
模块 5 的每个前沿问题）打分，并给出理由。

**分数锚点（必须照此打分，否则分数会挤在 6–8）**：

| 分数 | 判据 |
|---|---|
| 9–10 | 一手数据源 + 至少两个相互独立的来源佐证 + 材料可公开复核 + 已明确排除主要替代解释 |
| 7–8 | 有一个可靠一手来源或权威二手来源；存在少量未排除的替代解释或边界不清 |
| 4–6 | 依赖单一来源、二手转述、或利益相关方材料；或存在已知的反对证据未被处理 |
| 1–3 | 无来源 / 来源不可信 / 与已知证据冲突 / 本质是推测 |

打分时必须：
- 逐条检查引用的 `[S<n>]` **是否真的说了那句话**（回来源清单核对）。
  原论文实测约 15% 的句子「看起来有引用」其实没有支撑，这是最高频的失分点。
- 若一条结论的分数低于 6，必须写出**具体缺什么**。

## 评审项二 · 最薄弱环节

- 指出**最不可靠的那一条**结论，说清为什么。
- 给出**验证它所需的证据**，具体到可执行：
  需要什么类型的数据、从哪里能拿到、多大的样本/什么样的对照才够、或者说明
  「这个问题目前公开数据不足以验证」。
- 不要写「建议进一步研究」这类空话。

## 评审项三 · 偏见检查

1. **视角主导**：统计五个视角（从业者 / 学者 / 怀疑者 / 经济学家 / 历史学家）
   各自在报告中被引入的次数与篇幅占比。是否存在某一视角明显占据主导？
   若怀疑者视角的篇幅显著低于其他，直接判定为**偏见风险**（原论文最高频缺陷就是
   源偏见转移，编辑提及 12 次）。
2. **认知偏差**：指出具体类型，不要笼统说「可能有偏见」。常见项：
   - 确认偏误（只引用支持结论的材料）
   - 可得性偏差（只用最容易搜到的来源）
   - 时效性偏差（用旧数据描述现状，或未标注时间）
   - 利益相关方偏差（采用厂商/资助方自述而未标立场）
   - 过度关联（把两个来源都没说有关系的事实连起来 —— 原论文第二大缺陷）
3. **情绪化措辞**：搜索 `显著 / 革命性 / 史无前例 / 至关重要 / 极大地 / 众所周知`，
   无量化支撑的一律点名。

## 评审项四 · 缺失视角

- 除五个既定视角外，是否还有**会改变结论**的重要视角？
- 对每个提出的缺失视角，必须说明：**如果加入它，报告的哪条结论会改变、怎么变**。
  提不出后果的「缺失视角」不要写。

## 评审项五 · 终评（Stanford 教授角色）

扮演一位 Stanford 的教授评阅这份报告：

- **总分**：按研究生研讨课期末报告的标准打分（给出 x/100 或等级）。
- **这份报告目前能不能用**：一句话回答。
- **改进清单**：按「对结论影响从大到小」排序，最多 5 条，每条要具体到改哪里。
- 不要客套。评分与批评必须挂钩到上面四项的具体发现。

---

## 输出格式

写入 `70_review.md`：

```
# 同行评审

## 1. 逐条可信度
| 结论 | 分数 | 理由 |
| F1 ... | 8 | ... |

## 2. 最薄弱环节
- 结论：F3
- 原因：...
- 验证所需证据：...

## 3. 偏见检查
- 视角分布：从业者 x 条 / 学者 x 条 / ...
- 认知偏差：...
- 情绪化措辞命中：...

## 4. 缺失视角
- <视角名>：若加入，会改变 F2，因为 ...

## 5. 终评
- 总分：
- 能不能用：
- 改进清单：

## 6. 主 agent 处置记录（由主 agent 填写，不要由评审 agent 填）
| 评审意见 | 处置 | 理由 |
```

## 主 agent 的处置规则

- 每条评审意见必须二选一：**采纳（并说明改了什么）** 或 **驳回（并说明理由）**。
- 主 agent 有最终裁量权 —— 评审只是输入，不是命令。但驳回必须给理由，
  不能静默忽略。
- 修订后**不发起第二轮评审**。
